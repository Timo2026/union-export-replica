## 1. 项目概述

### 1.1 一句话定位

**Union·由你 — CNC AI 工艺大脑**：输入一句话或一张图纸，系统自动完成「意图识别→3D几何生成(TOT三管线)→DFM冲突检测→报价计算(13+材料×12表面)→一键打包交付」全链路。

### 1.2 核心设计哲学

- **离线优先**：`calc_quote` 纯数学零 AI，断网可用，规则引擎兜底
- **多模型自适应**：本地 Ollama → 云端 OpenAI 兼容 API → 规则引擎，三级降级链
- **白盒报价**：材料费/加工费/表面费三栏分解，公式可追溯
- **DFM 门禁**：36 条工艺不兼容黑名单，拦截不可制造组合
- **对外接单模式**：`EXTERNAL_MODE=1` 启用水印/有效期/金额门禁/未识别材料人工审核

### 1.3 核心能力矩阵

| # | 能力 | 状态 | 说明 |
|---|------|------|------|
| 1 | TOT 三管线几何生成 | ✅ | flange/sleeve/shaft/plate/box/bracket 6 种零件 |
| 2 | 5 专家会议编排 | ✅ | CEO/CFO/工艺主管/BI分析师/战略师，含否决/覆写 |
| 3 | SHA-256 链式审计 | ✅ | `AuditLogger` 防篡改，`verify_chain` 校验 |
| 4 | DFM 可制造性检测 | ✅ | 7 维度评分（壁厚/孔/复杂度/尺寸/表面/公差/刀具可达性） |
| 5 | 即时报价 | ✅ | 13+材料 × 12表面，白盒公式 |
| 6 | STEP 生成与解析 | ✅ | cadquery + cascadion + trimesh 三阶段降级 |
| 7 | 一键 ZIP 打包 | ✅ | STL + STEP + 报价 JSON |
| 8 | 模型自动发现 | ✅ | 9 模型探测，按 quality_score 排序选最优 |
| 9 | 批量报价引擎 | ✅ | 400+件批量，PDF→STEP→报价→DFM→工艺路线 |
| 10 | MTClaw FR 集成 | ✅ | Function Router 路由加速 CNC 垂域工具 |

### 1.4 技术栈

| 层 | 技术 |
|----|------|
| 后端 | FastAPI + Uvicorn (Python ≥3.11) |
| 前端 | 原生 HTML/JS + Three.js (3D 预览) |
| CAD | OCP 7.7.2.1 + cadquery 2.4.0 + trimesh 4.12.2 + cascadion 0.1.1 |
| 图纸 | pdfplumber (PDF) + ezdxf 1.4.4 (DXF) + openpyxl (XLSX) |
| AI 引擎 | Ollama (本地) / OpenAI 兼容 API (云端) / 规则引擎 (兜底) |
| 配置 | YAML (experts/skills) + JSON (models) |
| 审计 | SHA-256 链式哈希 |
| 部署 | conda / Docker / venv / bat 一键启动 |

### 2.2 核心数据流

```
用户输入 (一句话/STEP文件/PDF)
    │
    ├─ 意图识别 (cnc_quick.detect_cnc_intent)
    │
    ├─ 图纸解析 (drawing_parser / step_parser)
    │   ├─ PDF → pdfplumber 提取材料/表面/数量/公差/粗糙度/螺纹
    │   └─ STEP → cadquery(cascadion) → trimesh → bbox 降级
    │
    ├─ DFM 门禁 (neuro_core.conflict_check.ConflictChecker)
    │   └─ 36条黑名单 + 7维度评分
    │
    ├─ 报价计算 (app.main_lite.calc_quote)  ← 统一报价引擎
    │   └─ 材料费 + 加工费×公差×粗糙度 + 表面费 + 螺纹费 + 利润
    │
    ├─ 专家会议 (neuro_core.serial_expert)  [完整版]
    │   └─ 5专家投票，含否决/覆写
    │
    ├─ 审计日志 (safety.audit_logger.AuditLogger)
    │   └─ SHA-256 链式哈希
    │
    └─ 打包交付 (runtime.export_bundler.create_bundle)
        └─ STL + STEP + 报价JSON → ZIP
```

### 2.3 降级链

```

云端 API (MTClaw FR:7863 / OPC Cloud / StepFun)
```

## 4. 核心模块详解

### 4.1 app/main_lite.py — 核心后端入口

**职责**：FastAPI 服务入口，承载报价引擎 `calc_quote`、对话回复 `bot_reply`、STEP 上传报价、3D 预览、打包导出等全部核心 API。

**核心常量**（报价引擎参数）：

| 常量 | 用途 | 示例 |
|------|------|------|
| `MAT_COEFS` | 材料加工难度系数 | 6061→1.3, 304→1.5, tc4→5.4 |
| `MAT_PRICE_PER_KG` | 材料单价(元/kg) | 6061→200, 304→575, tc4→6267 |
| `MAT_FIXED_COEF` | 材料固定成本系数 | 6061→0.5, tc4→2.0 |
| `RAW_MATERIAL_PRICE` | 原材料基准单价 | 6061→25, 45钢→8 |
| `BIG_PART_MAT_PRICE` | 大件专用单价 | 6061→170, 304→130 |
| `SURF_COEFS` | 表面处理系数 | 阳极氧化→1.6, 镀铬→1.8 |
| `SURF_INVALID` | ★ 工艺不兼容黑名单(36条) | (6061,发黑)→"铝合金不做发黑" |
| `SURF_FIXED_FEE` | 表面处理固定费(元/件) | 阳极氧化→50, 镀镍→50 |
| `SURF_AREA_RATE` | 表面处理面积费率(元/dm²) | 阳极氧化→20, 镀铬→25 |
| `TOL_COEF` | 公差系数 | 精细→1.30, 中等→1.0, 粗糙→0.85 |
| `ROUGH_COEF` | 粗糙度系数 | Ra0.2→1.80, Ra0.4→1.60, Ra3.2→1.0 |
| `THREAD_FEE_PER_HOLE` | 螺纹孔附加费 | 5.0元/孔(默认), 316l→2.0元/孔 |

**核心函数**：

| 函数 | 签名 | 说明 |
|------|------|------|
| `calc_quote` | (material, surface, quantity, weight_kg, max_dim_mm, surface_area_dm2, tolerance, roughness_ra, thread_count, dim_x, dim_y, dim_z, price_mode) → dict | ★ 统一报价引擎，白盒公式 |
| `extract_params` | (msg) → dict | 从自然语言消息提取报价参数 |
| `bot_reply` | (message) → dict | 机器人回复主逻辑(含阶段0门禁) |
| `check_conflict` | (material, surface) → dict | 冲突检测(包装SURF_INVALID) |
| `_llm_parse` | (prompt, schema) → dict | 调用Ollama解析JSON |
| `detect_ollama` | () → bool | 检测Ollama可用性 |

### 4.2 src/core/fleet_coordinator.py — Agent 舰队协调器

**职责**：系统编排核心，将自然语言任务分解为多 Agent 串行 Pipeline。

**5 个 Agent**：

| Agent | name | 包装模块 | 职责 |
|-------|------|----------|------|
| DrawAgent | step-factory | step_generator_dual.generate_part | 几何生成+尺寸提取 |
| ConflictAgent | conflict-checker | neuro_core.conflict_check.ConflictChecker | DFM冲突检测 |
| QuoteAgent | quote-engine | runtime.quote_adapter.QuoteAdapter | 报价计算 |
| BundleAgent | output-bundler | runtime.export_bundler.create_bundle | ZIP打包 |
| RagAgent | rag-searcher | data.rag_engine.search | 知识检索 |

**3 套工作流模板**：

| 模板 | 步骤 | 适用场景 |
|------|------|----------|
| full | draw→conflict→quote→bundle | 完整方案生成 |
| draw_quote | draw→quote | 仅画图报价 |
| knowledge_quote | rag→quote | 基于知识报价 |

**Pipeline 数据流**：每步成功后将 `output` 注入所有依赖该步的下一步 `input_params`（`nxt.input_params.update(step.output)`）。

### 4.3 src/core/skill_bridge.py — Skill 桥接层

**职责**：将 ClawHub 标准 skill（SKILL.md + scripts/main.py）动态桥接到本项目。

**核心机制**：
- `scan()`：扫描 `_skill_extract/*/SKILL.md`，解析 frontmatter，检查 main.py 存在性（不 exec，避免超时）
- `_ensure_run_loaded()`：懒加载，`importlib.util.spec_from_file_location` 动态加载 main.py
- `call(name, request)`：直接调用 skill 的 run 函数
- `register_all(skill_caller)`：批量注册到 SkillCaller
- `get_skill_knowledge_summary()`：生成注入 LLM system prompt 的知识文本（按 DFM>CNC>材料>公差>刀具>表面>质量 优先级排序，总字符上限 8000）

### 4.4 src/runtime/step_parser.py — STEP 几何解析

**职责**：解析 STEP 文件提取几何信息（bbox/体积/面数）。

**三阶段降级**：
1. cadquery + cascadion（B-Rep 精确体积）
2. trimesh（水密网格体积）
3. bbox 估算（体积 = 长×宽×高 × 0.5 实心率）

**关键函数**：
- `extract_bbox_from_step(path)` → (dim_x, dim_y, dim_z, volume_mm3, error, volume_source)
- `estimate_volume_from_bbox(bbox)` → volume
- `get_material_density(material)` → density g/cm³

### 4.5 src/neuro_core/conflict_check.py — DFM 冲突检测

**职责**：工艺不兼容检测，基于 36 条黑名单规则。

**核心类**：`ConflictChecker`
- `check(material, surface, ...)` → {valid, conflicts, warnings, total_issues}
- 空表面处理守卫（P1-5 修复）
- 材料别名归一（经 material_utils.normalize_material）

### 4.6 src/safety/audit_logger.py — SHA-256 审计日志

**职责**：链式哈希审计日志，防篡改。

**核心方法**：
- `log(action, detail)` → 追加日志条目，每条含 prev_hash + curr_hash
- `verify_chain()` → 校验链完整性（已修复死代码缺陷）

### 4.7 batch_quote_engine.py — 批量报价引擎

**职责**：对 400+ 件批量执行 STEP解析→报价→BOM对照→验证矫正。

**核心函数**：
- `parse_spec(spec)` → (material_key, surface, surfaces, is_nonmetal, is_assembly, has_step)
- `weight_auto_fill(weight, volume, material, ...)` → (weight, is_filled) 重量自动补算
- `calculate_quote(item, step_path, batch_dir)` → 单件报价结果 dict
- `main()` → 批量主流程（BOM读取→逐件报价→自查矫正→导出CSV/JSON/MD）

### 5.2 config/tolerance.yaml — 公差与粗糙度

**公差等级**（ISO 286）：

| 等级 | 名称 | 系数 | 说明 |
|------|------|------|------|
| IT4 | 超精密级 | 1.8 | 需精密磨削 |
| IT5 | 高精密级 | 1.6 | 需精磨或坐标镗 |
| IT6 | 精密级 | 1.4 | 重要定位 |
| IT7 | 标准级 | 1.2 | 通用加工 |
| IT8 | 普通级 | 1.0 | 一般加工 |
| IT9 | 粗糙级 | 0.85 | 粗加工 |
| IT10 | 最粗级 | 0.7 | 毛坯余量 |

**表面粗糙度 Ra**：

| Ra | 名称 | 系数 | 工艺 |
|----|------|------|------|
| 0.2 | 镜面 | 2.5 | 研磨、抛光 |
| 0.4 | 超精 | 1.8 | 精磨 |

## 7. 报价引擎详解

### 7.1 calc_quote 白盒公式

```python
calc_quote(material, surface, quantity, weight_kg, max_dim_mm,
           surface_area_dm2, tolerance, roughness_ra, thread_count,
           dim_x, dim_y, dim_z, price_mode)
```

**计算步骤**：

```
1. 材料识别
   mat_key = material.lower()
   mat_coef = MAT_COEFS[mat_key]          # 加工难度系数
   mat_price = MAT_PRICE_PER_KG[mat_key]  # 材料单价(元/kg)
   fixed_coef = MAT_FIXED_COEF[mat_key]   # 固定成本系数

2. 冲突检测
   查询 SURF_INVALID[(mat_key, surface)]
   命中 → valid=False, conflicts=[...]

3. 成本明细
   material_cost = weight_kg × mat_price
   machining_cost = (80 + 0.15 × max_dim_mm) × fixed_coef
   setup_cost = (30 / quantity) × fixed_coef
   qc_cost = 20 × fixed_coef

4. 表面处理费(面积计价模型)
   surface_cost = SURF_FIXED_FEE[surface] + SURF_AREA_RATE[surface] × surface_area_dm2
   封顶：surface_cost ≤ 0.45 × (material_cost + machining_cost)

5. 公差/粗糙度系数
   tol_coef = TOL_COEF[tolerance]         # 精细1.30/中等1.0/粗糙0.85
   rough_coef = ROUGH_COEF[roughness_ra] 9  # Ra0.4→1.60, Ra3.2→1.0

6. 螺纹孔附加费(按材料分档)
   thread_fee = THREAD_FEE_PER_HOLE_BY_MAT[mat_key]  # 316l→2.0, 其他→5.0
   thread_cost = thread_count × thread_fee

7. 单价
   base_price = 15 + material_cost + machining_cost × tol_coef × rough_coef + setup_cost + qc_cost
   unit_price = base_price + surface_cost + thread_cost

8. 溢价调整
   quantity==1 → unit_price × 1.5(6061) 或 × 1.2(其他)
   薄板件(min_dim≤3且长宽比<30) → × 3.0(6061) 或 × 2.0(其他)

9. 批量折扣
   ≥100件→0.55 | ≥50→0.65 | ≥30→0.75 | ≥20→0.85 | ≥10→0.95 | ≥5→0.98
   total = unit_price × quantity × volume_discount

10. 双价格体系
    price_mode=="direct" → total × direct_ratio(默认0.85)
    profit_rate = 0.30(xometry) 或 0.25(direct)
    final = total × (1 + profit_rate)

11. 阶段0门禁(EXTERNAL_MODE=1)
    未识别材料 → quote_status="pending_material"
    final > AMOUNT_GATE_THRESHOLD → quote_status="manual_review"
    其他 → quote_status="auto"
```

## 14. 故障排查

| 问题 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: cascadion` | cascadion 未安装 | `pip install cascadion`（可选，cadquery fallback 可补偿） |
| STEP 尺寸过小/为0 | 单位错误(米制) | cadquery.importStep 为权威源，自动 ×1000 转毫米 |
| 报价费用 ¥0 | 材料未识别 | 检查材料名是否在 MAT_COEFS 中，或启用 EXTERNAL_MODE 进人工队列 |
| 交期为负数 | 计算异常 | 检查 quantity 和 weight_kg 是否为有效正数 |
| GBK 编码错误 | Windows 中文路径 | 确保文件路径无特殊字符，UTF-8 编码 |
| 端口 7862 占用 | 服务已运行 | `_restart_service.py` 重启或杀进程 |
| 模型不可用 | Ollama/云API未启动 | 检查 OLLAMA_BASE 环境变量，或配置 config/models.json |
| trimesh STEP segfault | 无效STEP文件 | 已修复：step_parser 返回 error 而非崩溃 |
| trimesh 挂起 | cascadion 缺失 | 已修复：调用前检查可用性，回退 cadquery |
